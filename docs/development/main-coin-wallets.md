## Что реализовано

- `/wallet`: основной баланс игрока, резерв, доступный остаток, баланс его организаций и история операций. Расходы организации разрешены её руководителю.
- Перевод основных монет любому игроку, с подтверждением суммы и получателя. Повторная отправка того же запроса не дублирует списание.
- Заявка на вывод: сумма резервируется сразу, реквизиты — свободный текст. Пользователь может отменить свою ожидающую заявку. Допущенный администратор после реального перевода вне сайта отмечает выплату; при отклонении/отмене резерв освобождается. Сайт не отправляет банковские платежи.
- `/admin/wallet`: ручное начисление, списание, обнуление, отмена перевода/коррекции, обработка вывода. Владелец назначает финансовый доступ конкретным администраторам; обычная роль администратора его автоматически не даёт. Каждое изменение записывается в журнал.
- Отмена потраченного перевода может создать долг. Поступления уменьшают долг, расходы ограничены доступным остатком. Бесплатные мероприятия и чат не блокируются.
- Старые `site_wallets`/`currency_ledger` используются исключительно для демо-ставок. Переводы, вывод и призовые используют отдельные таблицы `coin_*`. Демо-ставки и их выигрыши не пополняют основной кошелёк.
- Тренировки по умолчанию: 250 / 150 / 100 монет за итоговые места 1 / 2 / 3 сессии. При создании каждой сессии резервируются 500 монет организатора. Изменение плана в редакторе действует на новые, ещё не профинансированные сессии; существующий фонд сохраняет условия.
- Призы вычисляются сервером по опубликованным результатам и сохранённому фонду. На баланс команды/гильдии начисляется приз. Руководитель пока распределяет его игрокам переводами вручную.
- Исправление результатов отменяет прежнее распределение и проводит новое в одной транзакции. Повторная публикация того же финансового результата не создаёт повторных начислений. Отмена сессии отменяет призы и освобождает фонд.
- При недостатке средств автоматический планировщик не создаёт неоплаченную сессию, сохраняет сообщение о нехватке и уведомляет организатора. Уже созданные даты остаются; после пополнения следующая попытка продолжает расписание без дублей.

## Границы этой версии

- Контракты, автоматическое распределение по договорным долям, индивидуальные награды из фонда и покупка/продажа игроков/организаций ещё не реализованы. Их согласованные правила сохранены в документе обсуждения. Покупка монет отложена владельцем.
- Автоматические призы поддерживаются для обычной тренировки или одноэтапного турнира с одной общей таблицей. Многоэтапные и групповые призовые не включены.
- Если призёров меньше оплаченных мест, нераспределённая часть остаётся зарезервированной. Это позволяет исправить результат без повторного финансирования; отдельное закрытие остатка фонда пока не реализовано. Отмена сессии возвращает весь фонд и отменяет все её призы.
- Старые опубликованные результаты не создают задолженность организатора и не оплачиваются задним числом.
- Действующие резервы сохраняются даже после административного списания/обнуления. Отрицательный доступный остаток означает недостаток средств, а не снятие ранее принятых обязательств.

## Запуск и проверка

1. Из корня репозитория запустить `node scripts/dev-prize-staging.mjs`.
2. Открыть `http://127.0.0.1:3001/wallet`; вход указан в игнорируемом `tools/database-tests/artifacts/prize-wallets/local-test-login.md`. Это тестовый пароль, не пароль рабочего аккаунта.
3. Проверить перевод, резерв на вывод, отмену заявки; затем `/admin/wallet` и создание тренировки с фондом 500.
4. Данные не синхронизируются с рабочими балансами. Сохранённый вариант дизайна в другом checkout не изменён.

Миграции: `202610290003_main_coin_wallets.sql`, `202610290004_prize_reservations.sql`; ожидают предыдущие миграции новой стоимости/резервной очереди `.001` и `.002`.

Проверки: TypeScript, ESLint, безопасная production-сборка; полный набор PGlite-проверок БД (включая двойные запросы, права, долг, отмены, распределение и автоматическое расписание); браузерные сценарии кошелька. `tools/database-tests/smoke-prize-local.mjs` проверяет реальный локальный API со staging, выплаты подиуму и возврат фонда; снимки интерфейса и результаты записываются в игнорируемую папку артефактов.

Секреты и тестовые пароли находятся только в игнорируемой папке. Перед будущей публикацией требуется отдельное решение владельца о выпуске, актуальная резервная копия/проверка восстановления и проверка текущего остатка первоначального начисления. Настоящие банковские переводы этой проверкой не выполнялись.
