## Как проверить планировщик без побочных действий

Авторизованный запрос к `/api/cron/event-notifications?check=1` проверяет ключ и выполняет один ограниченный SELECT. Он не публикует мероприятия, не меняет санкции, не удаляет файлы и не отправляет уведомления. Ожидается HTTP 200 с `success: true, checkOnly: true`; неверный ключ — 401, недоступная база/ошибки окружения — 503 без раскрытия деталей.

В GitHub ручной запуск `Event notifications` по умолчанию использует `check_only: true`. Обычный запуск по расписанию или ручной запуск с `check_only: false` выполняет реальные операции и рассылки. Одновременные запуски блокируются общей группой concurrency.

Порядок восстановления после отсутствующих настроек:

1. Опубликовать проверенный код и дождаться зелёного `Site verification` и успешного Vercel deployment.
2. Проверить production через `?check=1` с существующим серверным ключом.
3. После разрешения владельца на возобновление автоматических публикаций и уведомлений установить GitHub secrets `SITE_URL` и `CRON_SECRET`.
4. Выполнить ручную проверку, затем штатный запуск; проверить оба результата в Actions.

## Supabase и низкая активность

На момент проверки оба проекта (`Ff-community`, `ff-update-2-staging`) имеют статус `ACTIVE_HEALTHY` и выполняют SELECT. В рабочей базе последняя миграция — `202610040001`. Тестовый проект содержит старую копию и не имеет таблицы журнала миграций Supabase: нельзя считать его автоматически синхронизированным с production.

Предупреждение о низкой активности на бесплатном тарифе означает возможную приостановку, а не немедленное удаление. Работающий планировщик выполняет необходимые приложению запросы, но бесплатный тариф не гарантирует отсутствие приостановок. Платный тариф не подключался. Уточнять имя проекта из письма, особенно если оно относится к редко используемой тестовой базе.

Источник: https://supabase.com/docs/guides/platform/free-project-pausing

## Ограничение проверки зависимостей

Полный `npm audit` на 04.10.2026 сообщает о `braces` и четырёх связанных пакетах в цепочке **инструмента разработки ESLint**, через `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`. Исправленной версии `braces` в официальном advisory нет. Эта цепочка не входит в production dependencies; пользовательские данные сайт через неё не обрабатывает. Не понижать Next и не отключать ESLint ради пустого отчёта. После выхода официального исправления обновить цепочку и повторить проверки.
