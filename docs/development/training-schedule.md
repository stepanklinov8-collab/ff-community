# Регулярные тренировки и прошедшие сессии

Внутри мероприятия завершившиеся по времени сессии скрыты под кнопкой «Прошедшие». Текущая сессия остаётся в расписании до окончания. Старые карточки раскрываются по десять; сведения о комнатах загружаются только для показанных карточек. Прямая ссылка на старую сессию раскрывает историю. Результаты и сами сессии не удаляются.

В редакторе мероприятия типа «Тренировка» доступен шаблон с автоматическим продлением. Он включается отдельно для каждого мероприятия и действует после сохранения/одобрения. Существующие мероприятия автоматически не переводятся на этот режим.

- Понедельник, вторник, четверг и воскресенье: 19:00–20:00, Москва.
- Регистрация: 10:00–18:59 того же дня.
- Первоначальная заявка принимается до закрытия регистрации. Изменение/отмена поданной заявки по-прежнему закрывается за десять минут до старта.
- Поддерживаются текущая и следующая календарные недели. В понедельник существующий планировщик добавляет следующую неделю; опоздавший запуск восполняет только будущие даты.
- Новая сессия содержит три разные карты. Цикл из пяти сессий: Бермуды/Некстера/Солара; Чистилище/Калахари/Бермуды; Некстера/Солара/Чистилище; Калахари/Бермуды/Некстера; Солара/Чистилище/Калахари. Каждая карта встречается трижды. Альпы и обновлённые Бермуды исключены. Позиция цикла сохраняется между неделями и выключением/повторным включением шаблона.
- Группы, лимиты и описание наследуются от последней обычной сессии. Комнаты, пароли и примечания к комнатам очищаются. Все группы новой сессии получают один порядок карт.
- Уже занятая дата, включая намеренно отменённую сессию, не создаётся повторно. Ручные изменения существующих сессий не перезаписываются. Отмена не перенумеровывает цикл ранее созданных сессий.
- Замороженные, отменённые, неопубликованные мероприятия и мероприятия с изменениями на рассмотрении не продлеваются.

Миграция `202610050001_recurring_training.sql` добавляет настройки шаблона, отметку периода и позицию ротации; сохраняет их в существующей транзакции редактора. Изменения шаблона непроверенного организатора требуют одобрения. Планировщик использует служебную функцию с тем же блокированием, что редактор; функция недоступна гостям и обычным пользователям. Проверка `check=1` не создаёт сессии.

Порядок публикации: SQL-проверки и сборка → миграция/откат на staging → браузерные проверки → резервирование/проверка восстановления → миграция production → публикация приложения. Не публиковать вызов нового планировщика до установки функции в рабочей базе.

На 05.10.2026 повторный полный экспорт PostgreSQL снова оборвался при чтении `pg_extension` через Supavisor. Снимок трёх изменяемых функций и сценарий отката не являются полноценной резервной копией пользовательских данных. До production требуется разрешение владельца на выпуск с этим конкретным ограничением либо рабочий полный экспорт с проверенным восстановлением. Проверка и откат на staging доступны независимо от этого ограничения.
