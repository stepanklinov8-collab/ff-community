# Заявки пополнения, уведомления и единый чат

Состояние: локальная разработка 5 ноября 2026. Production и его пользовательские данные не менялись. Миграция проверена в изолированной базе и установлена на выделенную staging после проверки отката. Перед публикацией нужны свежая проверенная резервная копия и применение новой миграции в production.

## Согласовано

- Основная валюта OMCITE Coins, прогнозы используют самостоятельные AP. Обмена между ними нет.
- Пополнение: пользователь подаёт заявку, договаривается с администрацией в чате, переводит деньги вне сайта. Уполномоченный финансовый администратор подтверждает фактическую оплату; сайт начисляет сохранённую сумму ровно один раз.
- Вывод: существующая заявка резервирует монеты; администратор переводит деньги вне сайта и подтверждает списание. Автоматических банковских платежей нет.
- ВК: сообщество `216519943` отправляет уведомления о новых заявках в личные сообщения `s.klinov12`. Переписка с игроками может оставаться в личных чатах, проверка оплаты — ручная.
- Старый пункт «Сообщения» удалён из навигации; кнопки связи администрации открывают «Чат». Прежние сообщения остаются доступными по старым ссылкам как архив, данные не удаляются.

## Реализация

`202611050001_funding_requests_notifications.sql`: приватные заявки и отдельный журнал идемпотентности. Организации пополняют собственный счёт; разрешены владелец и руководитель по действующим правилам. Подтверждение использует существующий `u6_coin_action(adjust)`, поэтому не обходит погашение контрактных долгов. Параметры счёта и суммы берутся из заблокированной заявки. Не более пяти ожидающих заявок от одного инициатора. Повторный запрос, потерянный ответ, отмена, отклонение не создают лишних монет.

Новые заявки пополнения/вывода в одной транзакции создают уведомления на сайте для финансовых администраторов и две записи очереди: push/VK. Банковские реквизиты, ФИО получателя, страна и тексты переписки в уведомления не включаются. Для пополнения передаются ник и контактная ссылка из профиля инициатора. Ссылка ведёт на конкретную заявку в `/admin/wallet`; её доступ проверяется заново. Исторические заявки не рассылаются задним числом.

Доставка выполняется после HTTP-ответа, при открытии финансовой админки и существующим планировщиком мероприятий (GitHub workflow раз в пять минут, возможны задержки самого GitHub). Отдельный защищённый endpoint `/api/cron/finance-notifications` поддерживает повтор. Ежедневный контрактный cron — дополнительная страховка. Проверка cron с `?check=1` ничего не отправляет. Каждая запись блокируется на две минуты; ошибка повторяется с задержкой до часа, без удаления записи. VK получает стабильный `random_id`; push — одинаковый tag при повторе. Отключённый канал не забирает заявки из очереди. Уже обработанная/отменённая заявка не порождает запоздалый запрос на действие.

## Настройки ВК сохранены; доставка ещё не проверена

5 ноября 2026 пользователь сохранил в Vercel Production `VK_FINANCE_COMMUNITY_TOKEN` как Secret; наличие подтверждено без раскрытия значения. Агент добавил недостающую `VK_FINANCE_RECIPIENT=s.klinov12` как Config для Production. Vercel подтвердил успешное сохранение. Настоящие сообщения ВК не отправлялись: новый код ещё не опубликован, действительность ключа и разрешение получателя на сообщения пока не проверены. Браузер отклонил доступ к `vk.ru` по site-safety policy. Не пытаться обходить ограничение другим браузером или скрытой автоматизацией.

Владелец самостоятельно создаёт ключ сообщества с доступом к сообщениям и помещает его в закрытую переменную окружения `VK_FINANCE_COMMUNITY_TOKEN`. Не передавать ключ в переписке, не писать в Git или NEXT_PUBLIC_. Получатель: `VK_FINANCE_RECIPIENT=s.klinov12`. Получатель должен разрешить сообщения сообщества. Перед включением проверить, что ключ принадлежит нужному сообществу. После подключения проверить доставку с владельцем; API-ошибки журналируются только кодом, без токена и реквизитов.

Наличие переменной означает только настройку, не доказанную доставку. Пуши требуют настроенного Firebase Admin и подписки устройства. Последующая публикация должна отдельно подтвердить работу реального планировщика и проверить ответ ВК; локальные сетевые тесты используют заглушку.

Для ВК использована официальная схема API: https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json . Предупреждения Кая и синхронизация с беседой в этот объём не входят.

## Уточнения формы и уведомлений 5 ноября

По ответу пользователя ФИО латиницей и страна перевода обязательны **только для вывода**. В форме, API и SQL новые заявки проверяются до резервирования. ФИО вводится латинскими буквами, страна — названием; автоматического перевода/транслитерации нет. Для старой истории поля остаются NULL, содержимое не выдумывается. Личная заявка видна её владельцу, организационная — текущему владельцу/руководителю, а финансовая админка — только допущенным администраторам. Реквизиты, ФИО и страна не включаются во внешние уведомления.

При создании пополнения ник и разрешённая контактная ссылка берутся из серверного профиля инициатора и фиксируются в закрытой очереди. Клиент не может подменить их телом запроса. Уведомления на сайте, push и VK используют эти данные; отсутствующий/некорректный контакт обозначается явно, без выдуманного адреса. В админской заявке доступны профиль и текущая контактная ссылка. Кнопка «Связаться с администрацией» из формы пополнения удалена по просьбе пользователя.

Для этих изменений создана отдельная миграция `202611050002_withdrawal_details_and_request_contacts.sql`: первую уже установленную миграцию не менять. Новая тоже установлена только на staging после ROLLBACK-репетиции и проверки отпечатков счетов; доказательство — игнорируемый `finance-details-staging-proof.json`. После этой установки файл неизменяем. Рабочая база и реальная доставка ВК по-прежнему не затронуты.
