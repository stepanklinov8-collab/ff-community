# Чат: первый выпуск

Локальная реализация от 24.10.2026. Публикация и изменения рабочей базы не выполнялись.

## Состав

- `/chat`: общий чат для подтверждённых зарегистрированных пользователей и одно закрытое обращение каждого пользователя ко всей администрации.
- Доступ к общему чату автоматический; отдельные записи членства и массовое добавление старых аккаунтов не нужны.
- Администраторы и суперадминистратор видят список обращений. Обычный пользователь видит только своё обращение. Личных диалогов между пользователями и пользовательских групп нет.
- Текст, emoji, ответы на сообщения, аватары и ссылки на профили, закрепления, непрочитанные чаты, полная история страницами по 50 сообщений.
- Только администрация редактирует, удаляет и закрепляет сообщения. При удалении текст стирается, остаётся отметка об удалении; скрытая копия исходного текста не сохраняется.
- Обычный пользователь может явно уведомить администрацию. Администратор — администрацию, выбранного участника с доступом к этому чату или всех в общем чате.
- Явные уведомления используют существующую таблицу уведомлений сайта. Email и push этим выпуском не отправляются. Другие сообщения отмечаются только как непрочитанные.
- Действующие дисциплинарные ограничения запрещают отправку в общий чат, сохраняя чтение и обращение в администрацию. Ручной мут можно выдать отдельно в нужном чате, либо всем обычным участникам общего чата; от 30 минут или бессрочно, причина необязательна. Администраторов мутить нельзя.
- Гостю доступно только приглашение войти. Переписка и количество пользователей не раскрываются.

## Технические решения

`src/modules/chat` изолирован от остальных бизнес-модулей, использует платформенные адаптеры. Страница имеет отдельную границу ошибок. Существующий раздел `/messages` сохранён.

Флаг `OMCITE_MODULES=chat=public` включает модуль; `chat=preview` подчиняется существующим правилам предпросмотра. Без флага модуль выключен, API и страница закрыты. Если в переменной уже есть другие модули, добавить `chat=public` через запятую, сохранив их.

Миграция `supabase/migrations/202610240001_chat.sql` добавляет таблицы `chat_rooms`, `chat_messages`, `chat_reads`, `chat_mutes`, `chat_actions`. Доступ к бизнес-таблицам и RPC закрыт для `anon` и `authenticated`. Сервер получает пользователя из проверенной авторизации, валидирует вход и вызывает RPC от сервисной роли; указать чужого пользователя в запросе нельзя. Чтение и каждое действие повторно проверяют доступ в базе.

Приватный Supabase Realtime получает от приложения пустую подсказку об изменениях; размещённый сервис добавляет служебный ID события. Текст, имена, идентификаторы сообщений и счётчики в подсказку не входят. Данные загружаются через авторизованный API с `private, no-store`. Политика `chat_receive_hints` проверяет права на канал. Открытая до отзыва роли подписка не получает содержимое новых сообщений. При отказе API приватная история очищается в интерфейсе.

Подписки работают только на странице чата. События объединяются с задержкой 300 мс. После фокуса/восстановления связи данные сверяются повторно; при открытой видимой странице есть резервная сверка раз в 60 секунд, без подключения — раз в 30 секунд. Ошибка отправки Realtime-подсказки не отменяет сохранённое сообщение. Счётчик бокового меню обновляется раз в минуту, при фокусе и прочтении. Скрытая вкладка не выполняет эти фоновые запросы.

Технические ограничения первого выпуска: сообщение до 4000 символов, не чаще одного в секунду; явное оповещение не чаще одного в 30 секунд на отправителя; до пяти закреплений в чате. Все ограничения проверяются сервером и базой, а не только кнопками. Повтор запроса использует тот же UUID, поэтому потеря ответа не создаёт повторного сообщения или уведомлений. Черновики и контекст ответа сохраняются при переключении чатов в рамках открытой страницы; после перезагрузки страницы черновики не восстанавливаются.

Срок хранения истории не ограничен по возрасту. Окончательное удаление аккаунта удаляет его сообщения и собственное обращение через внешние ключи; тексты удалённых сообщений и исторические копии правок не сохраняются. Журнал административных действий хранит только идентификаторы и тип действия. Истёкшие ручные муты больше не действуют по времени базы и очищаются при следующем запросе к чату.

## Проверки и запуск

Результат на 24.10.2026: проверки границ модулей, полный ESLint, production-сборка с TypeScript, 48 модульных/доменных тестов, весь SQL-набор и 33 браузерных сценария прошли. В браузерном наборе пять сценариев посвящены чату; остальные проверяют существующие разделы сайта.

- `node scripts/check-boundaries.mjs`
- `node --test --test-isolation=none tests/chat.test.mjs`
- `node tools/database-tests/verify.mjs`
- `node node_modules/eslint/bin/eslint.js .`
- Изолированная production-сборка с `safeTestEnv()` и `next build --webpack`.
- `node node_modules/@playwright/test/cli.js test` после сборки.

SQL-проверки выполняют настоящую миграцию в одноразовой PGlite-базе: права, закрытые обращения, RLS каналов, запреты модерации, уведомления, повторы, последовательность прочтения, смена ролей, муты, пагинация, антиспам, лимит закреплений и отказ доставки подсказки. Браузерные проверки моделируют Auth и транспорт: гостевой доступ, отправку/ответы, потерю ответа и повтор после перехода в другой чат, закрытое обращение, модерацию, ограничения, отзыв доступа и ширину мобильного интерфейса. Реальные SQL-проверки дополняют, а не заменяют эти браузерные сценарии.

`npm run dev` включает чат на `http://127.0.0.1:3000/chat` и использует изолированное локальное окружение. Сам по себе этот запуск не создаёт локальный Supabase: для реального входа и переписки нужен отдельный тестовый backend с миграцией. Production-ключи в безопасный запуск не передаются.

24.10.2026 перед выпуском восстановлен отдельный Supabase staging и применена миграция. Проверены три временных аккаунта: реальная приватная WebSocket-подписка, отправка через API, отсутствие дубля при повторе, закрытое обращение, отказ постороннему, запрет прямого чтения таблиц, мут с сохранением обращения в администрацию, отзыв роли администратора и переписка двух браузеров без перезагрузки. Все тестовые аккаунты и их тестовые кошельки удалены. Контрольная нагрузка: 40 авторизованных чтений при параллельности 5, без ошибок; p95 574 мс, максимум 593 мс с локального ПК до staging. Это ограниченная проверка, не гарантия работы при любой аудитории или превышении квот Realtime.

Полный production-дамп PostgreSQL/Auth сохранён локально в исключённом из Git каталоге `tools/database-tests/artifacts/chat-release`; проверены контрольная сумма и состав архива. Миграция добавляет только таблицы, функции и политику чата. При проблеме после выпуска модуль можно выключить через `OMCITE_MODULES` и вернуть предыдущий деплой, сохранив уже принятые сообщения в базе. Новые таблицы с пользовательской историей при таком откате не удалять.
