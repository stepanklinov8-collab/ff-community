# Активность пользователей интеграция ВК и отдельные очки прогнозов

Состояние на 01.11.2026. Новое обновление не опубликовано. Рабочие данные не менялись.

## Подготовлено локально

В админ-панель добавлена ссылка на `/admin/analytics`: период до 90 дней, поиск аккаунта по никнейму, визиты, просмотры, приблизительное активное время, последняя связь с сайтом, активные аккаунты, история последних 100 страниц и тип экрана. API доступен администраторам и суперадминистратору; модераторы и обычные игроки не получают статистику. Ответы private/no-store, таблицы закрыты RLS, публичных SELECT нет.

Трекер работает только после входа. Сохраняет нормализованный маршрут без параметров, значений форм и содержимого переписки; UUID сущностей заменяются `:id`. Подтверждённый JWT определяет владельца записи, клиент не передаёт чужой userId. Время рассчитывается по серверным отметкам с единственными часами аккаунта под блокировкой: две вкладки не удваивают его. Учитывается видимая вкладка в фокусе с взаимодействием за последние 120 секунд. Фоновая вкладка не добавляет активное время; длинный разрыв не начисляется. Heartbeat раз в 25 секунд, серверный предел одного интервала 45 секунд и защита частых повторов. Это оценка вовлечённости, не доказательство нахождения человека у устройства. Новый визит начинается после 30 минут отсутствия сигналов. История хранится 90 дней, очистка подключена после ежедневного обслуживания договоров; её ошибка не отменяет финансовую работу.

Основные OMCITE Coins остаются в `coin_accounts` / `coin_entries`. Прогнозы уже используют отдельные `site_wallets` / `currency_ledger` / `site_bets`. Выделен отдельный форматтер и рабочее название **Arena Points / AP**. Интерфейсы прогнозов, их админки и блока кошелька не используют значок основной монеты. API сообщает отдельное имя. Значения балансов, действующие ставки и выплаты не пересчитываются; обмена, вывода и перехода AP в контрактные/призовые средства нет. Название предложено пользователю; подтверждение пока не получено, его можно заменить без изменения числовых данных.

Миграция `202611010001_user_activity_and_forecast_points.sql` уже применена ТОЛЬКО к `swjdbeelqzdleefscuuc` после пробного отката и сравнения профилей/организаций/составов/двух балансов. Не редактировать её после этой установки. Любые дальнейшие изменения SQL — следующей миграцией. У fixture-проекта нет CLI-журнала `supabase_migrations.schema_migrations`; контрольный SHA записан комментарием таблицы и в игнорируемом локальном proof. Production не затронут.

## Требуются ответы и доступ

Яндекс Метрика — дополнительная общая аналитика. Счётчика в исходном коде не найдено; пользователь уточняет, существует ли он в его аккаунте. До предоставления номера никакой сторонний счётчик или передача идентификаторов посетителей не включены. Собственная статистика аккаунтов от Метрики не зависит и не восстанавливает прошлые посещения до внедрения.

Кай — нужна точная ссылка на используемого бота, беседа и подтверждённый способ управления ботом. Публичный API выдачи предупреждений не подтверждён. Не выдумывать endpoint/команду и не считать отправленное в беседу сообщение подтверждённым предупреждением Кая. Уточняется, кому адресовать командное/гильдийное предупреждение: лидеру, владельцу или конкретным игрокам. Простая редактируемая контактная ссылка профиля не подтверждает владение аккаунтом ВК; для наказаний нужна проверенная привязка VK ID.

После подтверждения возможности интеграции: серверная очередь после активации предупреждения, уникальность по ID предупреждения/действию/беседе/получателю, безопасные повторы, журнал доставки и отдельное подтверждение результата Кая. Ошибка ВК не откатывает выданное на сайте предупреждение. Для отмен/истечения и исторических предупреждений нужно согласовать правила синхронизации; старые преды не отправлять автоматически задним числом. Токены не хранить в браузере или Git. Не отправлять реальные тестовые преды людям.

## Проверки

`tests/analytics-and-points.test.mjs` — маршруты без токенов/параметров, окно активности и различие валют. `tools/database-tests/analytics.mjs` — подлинная миграция в PGlite: анонимный отказ, чужие visit/view ID, две вкладки и повторы, простой, роли/приватность, 90-дневная очистка и неизменные оба баланса. Включено в общий verify. TypeScript и ESLint текущих изменений прошли. Реальная проверка локального интерфейса выполняется только с выделенной staging и тестовым входом; приватный токен не передавать в публичный Preview.

Финальные результаты: production-сборка `scripts/safe-build.mjs` успешна; границы модулей сохранены; все SQL-сценарии `tools/database-tests/verify.mjs` прошли; 3 доменных теста аналитики/валюты и 6 браузерных сценариев кошелька прошли. Повторный `smoke-activity-local.mjs` проверил вход тестового администратора, реальный отчёт API с private/no-store, доступ гостя 401, интерфейсы 1280 и 390 пикселей без переполнения страницы и отдельное отображение AP. Скриншоты и логи находятся в игнорируемой папке `tools/database-tests/artifacts/contracts/activity-*`. Локальный сервер запускается через `tools/database-tests/start-contract-staging.mjs` на `http://127.0.0.1:3001`, раздел — `/admin/analytics`. Production и реальные кошельки не изменялись; Кай и Метрика не подключены, ожидаются ответы пользователя.
