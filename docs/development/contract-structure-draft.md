# Структура договора: обсуждение перед включением подписания

29.10.2026. Пользователь предложил подробнее согласовать обязательные пункты и способ исполнения условий. Подписание и контрактные выплаты не включать до фиксации результатов этого обсуждения. Уже принятые решения о владельцах, долях, штрафах, гостях и сделках остаются в силе.

## Способ исполнения

Уточнения 29.10 о минимальном участии и неявке:

- При недоборе договорного минимума игр **нет всех выплат за эту сессию**, в том числе оплаты игр/сессии, киллов/MVP и доли призовых. Зарплата за время действия договора — отдельное ранее согласованное обязательство.
- Штраф применяется только при явном пункте договора, если игрок был заявлен и полностью не явился. Частичное участие ниже минимума само по себе не является неявкой. Технический срыв не доказывает неявку; отменённые сессии не штрафуются.
- Способы штрафа: фиксированная сумма, процент стоимости игрока, сочетание суммы и процента с выбором большего/меньшего (не сложение). Без пункта штраф равен нулю, старые версии не переписываются.
- Недостаток монет создаёт долг игрока перед организацией, вывод до погашения запрещён. Владелец может отменять штрафы и начисления; требуется история, а не удаление финансовых записей.
- Дополнительно подтверждено: процент использует стоимость **на начало сессии**, не сегодняшнюю стоимость и не цену на публикацию. При пропущенном снимке нельзя подставлять текущую цену как историческую.
- Владелец вправе отменять и уже выплаченное начисление. С игрока возвращается только доступная незарезервированная сумма. Остаток — отдельный долг организации, автоматически возвращаемый при новых поступлениях игроку. Не делать немедленный минус на всю сумму и не расходовать целевые резервы. Это новая модель долга игрока и исключение из прежнего общего администраторского обратного перевода; долг организации игрокам по-прежнему погашается вручную.
- Вопросы этого этапа закрыты. Начисление/отмена штрафа, исторический снимок цены и автоматический возврат частями пока требуют реализации; один конструктор не выполняет списания.

Автоматически исполняются только структурированные поля. Сайт не определяет сумму списания, запрет участия или срок договора по произвольной фразе и не использует ответ языковой модели как финансовое распоряжение.

Утверждённый интерфейс: конструктор обязательных условий → читаемый полный текст, собранный из заполненных полей → проверка сторонами → подтверждение одной и той же неизменяемой версии. **Все условия задаются исключительно конструкторами. Свободного текста обязательств нет.** Для новых потребностей пользователей добавляются новые типы пунктов и подготовленные формулировки.

## Обязательные разделы

| Раздел | Данные для автоматического исполнения |
|---|---|
| Стороны | ID игрока, ID организации, тип договора, полномочия представителя. ФИО/ник не заменяет устойчивый ID. |
| Срок | Начало; явный выбор: до даты, бессрочно, лимит игр/тренировок/турниров. Сочетание даты и лимита должно быть понятно в итоговом тексте. |
| Область участия | Основной договор или временное выступление за конкретное мероприятие/сессию. Гостевой договор не меняет постоянный состав. |
| Призовые | Доли тренировок, турниров и личных наград; явное указание базы процента. Доли конкретной выплаты суммарно не выше 100%. |
| Фиксированная оплата | Сверх доли призовых: разово при подписании, за сыгранную игру, сессию или турнир. Сумма, основание, плательщик, момент начисления и резерв. Обеспечение и детали исполнения ещё согласуются. |
| Дополнительные бонусы | За MVP, каждый килл, место своей команды в рейтинговой таблице за заданный период. Тип награды, область событий, сумма, подтверждённый факт; для рейтинга — таблица, место/топ, период и способ проверки. Не путать с личным призом из фонда организатора. |
| Регулярная зарплата | Сумма за выбранное положительное целое число дней, выплата в конце периода за время действия договора. Нехватка денег не прекращает договор и начисление. После недели неоплаты игрок вправе расторгнуть без штрафа. Границы периодов, неполный период и компенсации уточняются. |
| Исключения мероприятий | Выбор мероприятия по ID и изменяемых условий. Общие условия и исключения утверждены. Предлагаемый приоритет: явно переопределённый пункт заменяет общий, остальные наследуются; подтвердить до исполнения. |
| Фактическое участие | Полная доля за любое участие; пропорционально играм; полная доля после минимума игр. |
| Другие организации | Разрешено / запрещено / требуется согласие; обязательства перед каждой действующей основной организацией. |
| Платный переход | Нужное согласие; фиксированная компенсация либо процент согласованной цены перехода. Исключение при превышении цены согласуется в сделке. |
| Выход игрока | Явно «без компенсации», фиксированная сумма либо процент расчётной стоимости на момент подтверждения и оплаты. Возможен согласованный платёж третьего лица. |
| Досрочное прекращение | Инициатива каждой стороны, применимые компенсации; обоюдное согласие без штрафа; спор через администрацию. |
| Выплата и исправление результатов | Источник призов — резерв организатора; округление долей вниз, остаток организации; исправление отменяет прежнее распределение, при расходовании монет возможен долг. Фиксированную оплату и зарплату не списывать из призового резерва без отдельного согласованного основания. |
| Подтверждение | Обе стороны подтверждают одну версию. Изменение текста/полей не изменяет уже принятые условия задним числом. |

Обязательность пункта означает обязательный явный выбор, а не обязательную ненулевую выплату/штраф. Предзаполненные значения не должны незаметно становиться обязательствами.

## Пример одинакового процента с разными правилами участия

Приз организации 250 OC, доля игрока 20%, участие в одной из трёх игр:

- Любое участие: 50 OC.
- Пропорционально играм: floor(250 × 0,20 × 1/3) = 16 OC.
- Минимум две игры: 0 OC.

Именно поэтому слова «20% призовых» недостаточны без выбора правила участия, базы выплаты и области действия.

## Каталог конструкторов и подготовленных текстов

Каждый тип пункта содержит: постоянный код, версию схемы, допустимые поля и значения, проверку совместимости с другими пунктами, версию подготовленного текста, источник подтверждённых фактов, событие исполнения и проверяемое правило расчёта. Произвольный текст, исполняемые скрипты и ответы ИИ не являются условиями или финансовыми распоряжениями.

Пример шаблона: «Организация выплачивает игроку {share}% от {prizeKind} при {participationRule}». Поля share, prizeKind и participationRule используются и для текста, и для серверного расчёта. Одного текста без соответствующих проверенных полей недостаточно для подписания.

Новый тип условия проходит разработку схемы, проверки, события исполнения, текста и тестов. После этого он доступен для новых договоров или согласованных изменений. При недостатке конструктора стороны запрашивают его добавление; нельзя обходить отсутствие типа через поле примечания.

Подписанная версия хранит выбранные типы, их версии, значения и точный сформированный текст, а также подтверждения сторон. Обновление шаблона не меняет ранее подписанные условия. Неизвестный или неподдерживаемый тип нельзя молча игнорировать и всё равно подписывать договор.

При проверке исключений рассчитывается совокупность фактически применимых условий всех действующих договоров: общие доли не складывать повторно с заменяющими их долями мероприятия. Личные награды и командные призы имеют разные базы. Две конфликтующие настройки одного пункта для одного мероприятия должны быть отклонены, а не разрешены порядком массива.

## Полученные ответы 29.10.2026

1. Только конструкторы и подготовленные тексты. Новые конструкторы добавлять по запросам пользователей.
2. Кроме долей призовых и личных наград нужны фиксированная оплата и регулярная зарплата.
3. Общие условия могут иметь исключения для выбранных мероприятий.
4. Фиксированная оплата: доступны разовая выплата при подписании и выплаты за сыгранную игру, сессию, турнир.
5. Дополнительно доступны бонусы за MVP, каждый килл и определённое место команды в рейтинговой таблице за указанный период.
6. Зарплата выплачивается в конце периода за время действия договора. Длина периода задаётся произвольным положительным целым числом дней, не только неделей или месяцем.
7. При недостатке средств договор продолжает действовать, задолженность может расти. Организация имеет неделю на погашение наступившего долга; после этого игрок получает право досрочного расторжения без штрафа с предусмотренными договором выплатами. Автоматического расторжения из-за долга нет.
8. Бонус рейтинга: в конструкторе доступны место на конец периода, лучшее место за период, удержание в выбранном топе весь период. Таблица рейтинга, цель и период выбираются в договоре.
9. При расторжении из-за просрочки сохраняются вся задолженность и заработанное до расторжения. Отдельная компенсация выбирается в договоре: нет, фиксированная сумма, процент задолженности. При недостатке средств суммы остаются долгом организации; отсутствие денег не блокирует такое расторжение.
10. Периоды зарплаты отсчитываются от начала действия договора, выплата каждые N суток. Последний неполный период оплачивается пропорционально времени действия, с округлением вниз до целой монеты. Семь суток на погашение считаются от установленного срока каждой выплаты.
11. При подписании обязательно резервируются разовая оплата и зарплата первого периода. При нехватке доступных денег подписание не допускается. Следующие зарплатные периоды резервируются перед их началом; бонусы за киллы/MVP/рейтинг оплачиваются после подтверждения результата. Нехватка денег по действующему договору создаёт долг, а не прекращает договор.
12. Долги распределяет вручную руководитель или владелец организации. Автоматическое направление свободных средств на старейшие долги и пропорциональное распределение между кредиторами НЕ выбраны. При наличии долга вывод организации запрещён. Общий запрет покупок и новых обязательств из предложенного варианта НЕ утверждён; для них сохраняются обычные проверки доступного баланса, полномочий и необходимых резервов.
13. Для процентной компенсации в конструкторе выбирается база: сумма, указанная в договоре; расчётная стоимость игрока; вся задолженность по договору. Значение базы фиксируется на момент подтверждения расторжения. Саму компенсацию в базу повторно не включать.
14. Специальное условие мероприятия заменяет соответствующее общее условие, остальные пункты сохраняются. Пример: 30% за выбранный турнир заменяют обычные 20%, зарплата продолжает действовать. Применимая подписанная версия фиксируется перед началом сессии и не изменяется задним числом.
15. Допустимо указать одновременно фиксированную сумму и процент, выбрав большее либо меньшее из двух значений. Это выбор одного результата, а не сложение суммы с процентной частью. Поле выбора обязательно; нет скрытого выбора по умолчанию.
16. **Продление договора не начисляет повторно приветственный бонус или сумму выкупа.** Продление и новая редакция условий не являются новой покупкой игрока. Первоначальные начисления, оплата и непогашенный остаток сохраняются в истории без дублирования.

## Продление без повторения первоначальных платежей

Приветственный бонус относится к первоначальному соглашению, а выкуп — к отдельной сделке перехода. Ни номер новой версии, ни новая дата окончания, ни повторное подписание продления не являются основанием для повторного начисления, резервирования или перевода этих сумм.

В будущей цепочке исполнения использовать постоянный идентификатор первоначального соглашения/цепочки продлений и уникальность первоначального бонусного обязательства. Если продление представляется новой записью договора, сохранять явную связь с исходным соглашением; новый ID записи не должен обходить уникальность. Для выкупа уникальность определяется исходной сделкой, не договором или его редакцией.

Если первоначальный бонус или выкуп ещё не оплачен, продление сохраняет исходное обязательство и его остаток: не прощает долг и не создаёт его второй раз. Изменение суммы приветственного бонуса в новой редакции не превращать в автоматическую доплату. Отдельные новые согласованные награды требуют отдельного предусмотренного конструктора и основания; не маскировать их под повторение старой оплаты.

При включении подписания и выплат обязательны тесты: первое подписание создаёт единственное первоначальное обязательство; повтор запроса идемпотентен; продление срока, новая версия, повторное подтверждение продления и цепочка из нескольких продлений не меняют количество/сумму первоначальных начислений. Проверить оплаченный и неоплаченный первоначальный бонус, частичную оплату и существующую сделку выкупа. Сейчас эти требования не подтверждены платежными интеграционными тестами: подписание и выкуп ещё не включены.

## Комбинированная компенсация

Конструктор предусматривает четыре режима: нет компенсации; фиксированная сумма; процент выбранной базы; сумма и процент с выбором максимума/минимума. Для последнего режима A — фиксированная сумма, B — значение выбранной базы, p — процент. Процентная часть P = floor(B × p / 100), итог C = max(A, P) либо min(A, P). Базовая сумма для процента и фиксированная часть — разные поля: их не подменять друг другом.

При A = 1 000 OC, B = 15 000 OC, p = 10% процентная часть равна 1 500 OC: максимум даёт 1 500 OC, минимум 1 000 OC. При B = 5 000 OC процентная часть 500 OC: максимум 1 000 OC, минимум 500 OC. При B = 0 минимум равен нулю, максимум равен фиксированной сумме. При равенстве выплачивается одно значение, не удвоенное.

Текст договора и предварительный расчёт используют одни и те же проверенные поля. Для разных оснований компенсации доступны только применимые базы: например, цена перехода для перехода; для расторжения из-за долга — три базы из п. 13. Не переносить автоматически расчёт от задолженности на все остальные виды компенсации.

## Резервы, долг и ручное погашение

Резерв удерживает существующие монеты конкретного плательщика под конкретное обязательство. Не включать уже зарезервированную сумму в доступные средства для другого договора. Не создавать разовую оплату или первый зарплатный период без покрытия при подписании. Проверка достаточности, создание резервов и принятие версии должны быть одной транзакцией: при неудаче договор не становится подписанным, частичные резервы не остаются.

Обычная выплата из целевого резерва по наступившему сроку и погашение ранее возникшего долга — разные операции. Выбор ручного погашения долгов не отменяет согласованную выплату зарплаты в конце периода. Недостаток резерва для следующего периода не должен ускорять установленный срок выплаты: семь суток считают от срока выплаты, а не от момента неудачной попытки резервирования.

В интерфейсе долгов руководитель/владелец видит игрока, договор, основание, срок выплаты, первоначальную сумму, оплачено, остаток, срок погашения и доступное право расторжения. Для ручной оплаты выбирает конкретные обязательства и сумму. Частичная оплата допустима в пределах остатка; переплата, отрицательная сумма и повторное списание одного запроса не допускаются. Делегированный доступ к конструктору не даёт права оплачивать долг.

Наличие непогашенного обязательства с наступившим сроком блокирует вывод организации сразу; не ждать окончания семи суток. Семь суток определяют право игрока на расторжение, а не начало запрета вывода. Предстоящая зарплата, срок которой ещё не наступил, не является просроченным долгом. Чужие и целевые резервы не использовать для ручного погашения другого обязательства.

Проверку долга выполнять на сервере для операций вывода, а не только скрывать кнопку. Существующие переводы и права владельца не расширять автоматически в способ обойти запрет: правила обычных переводов при долге и уже созданных заявок на вывод требуют отдельной проверки при реализации, без скрытого приравнивания всех расходов к выводу.

## Конструкторы выплат: состав полей для реализации

Поля ниже реализуются в конструкторе предложений; сохранённое предложение не является подписанным договором и не выполняет выплаты.

| Тип пункта | Поля и источник фактов |
|---|---|
| Разовая оплата | Сумма OC; только первоначальное заключение соглашения. Продление, новая версия и повторный запрос не создают её повторно. |
| За участие | Сумма OC; единица «игра / сессия / турнир»; область мероприятий; правило фактического участия; подтверждённые результаты. Счётчик турнира не увеличивается за каждую его игру или этап. |
| MVP | Сумма OC за награду; вид/уровень награды и область мероприятий; подтверждённый получатель. Не назначать MVP по совпадению текста ника. |
| За килл | Сумма OC за один личный килл; область мероприятий; опубликованная личная статистика, связанная с ID игрока. Не подставлять киллы команды при отсутствии личных данных. |
| Место организации | ID организации, рейтинговая таблица, целевое место/диапазон, начало и конец периода, способ проверки (конец / лучшее / удержание весь период), сумма OC. Потребуется история снимков рейтинга; сегодняшний рейтинг не доказывает место в прошлом. |
| Зарплата | Сумма OC за период, N дней, начало, срок выплаты, начисленное/оплаченное/остаток долга, срок погашения каждого обязательства. Периоды от начала договора; неполный последний период пропорционально времени, округление вниз. |
| Просрочка и расторжение | Привязка к неоплаченным обязательствам, 7 суток от срока каждой выплаты, явное подтверждение игрока. Компенсация: нет / фиксированная / процент выбранной базы / сумма и процент с выбором большего или меньшего. Долг и заработанное сохраняются. Проверка срока и непогашенной задолженности повторяется на сервере при подтверждении. |

Каждое начисление связано с договором, неизменяемой версией пункта и фактом-основанием. Начисленное обязательство и фактический перевод монет — разные записи: нехватка баланса не должна создавать фиктивную выплату. Исправления результатов требуют корректирующих записей с сохранением истории. Частичная оплата уменьшает остаток конкретного долга и не должна незаметно сдвигать его первоначальный срок.

Бонус MVP от организации по договору и личная награда MVP от организатора мероприятия — разные источники. Не списывать договорный бонус из фонда мероприятия и не создавать монеты для погашения задолженности. Новые бонусы относятся к выплатам, а не к изменению формулы спортивного рейтинга или стоимости.

## Результат последних уточнений

Оба отправленных вопроса закрыты: выбор базы компенсации задаётся в конструкторе (п. 13), порядок исключений и фиксации версии утверждён (п. 14). Дополнительно принят комбинированный режим (п. 15). Эти решения повторно не спрашивать.

Не назначать неподтверждённые финансовые правила скрытыми значениями по умолчанию. Изменение действующего договора не должно случайно повторять ранее выплаченную разовую оплату; новая дополнительная оплата требует явно согласованного нового обязательства.

## Проверяемые примеры утверждённых правил

- Зарплата 1 000 OC каждые 10 суток. Начало 01.11.2026 12:00 МСК: первая выплата 11.11.2026 12:00 МСК, вторая 21.11.2026 12:00 МСК. Это интервалы по 24 часа, не календарные недели/месяцы.
- Если первая выплата не погашена, семь суток истекают 18.11.2026 12:00 МСК. Просрочка второй выплаты имеет собственный срок. Частичная оплата первой не переносит её срок погашения.
- Если договор закончился через 3,5 суток после последней полностью начисленной десятидневки, последний период даёт floor(1 000 × 3,5 / 10) = 350 OC. Уже начисленные полные периоды повторно не начисляются.
- Если прошло семь суток неоплаты, но игрок не подтвердил расторжение, договор продолжает действовать и начислять зарплату. Планировщик не должен автоматически прекращать его.
- При подтверждённом расторжении из-за долга штраф игрока за обычный досрочный выход не применяется. Неоплаченные начисления и договорная компенсация остаются обязательствами организации после окончания договора.
- За выбранный период команда последовательно занимала места 4 → 2 → 5. Для условия «топ-3»: лучшее место — условие выполнено; место в конце — не выполнено; удержание весь период — не выполнено. Проверять по сохранённой истории, не по сегодняшнему месту.
- Повторное выполнение фоновой задачи, повторный запрос и исправление публикации не должны создавать дубликаты выплат. Пропуск запуска задачи не сдвигает первоначальные сроки зарплаты и долга на время запуска.
- Доступно 1 200 OC, разовая оплата 300 OC, зарплата первого периода 1 000 OC: подписание отклоняется целиком, несмотря на достаточность средств для каждого пункта по отдельности. При доступных 1 300 OC совместное покрытие возможно.
- Два игрока имеют долги 600 и 400 OC, доступно 500 OC. Поступление этих 500 OC само по себе не оплачивает долги. Руководитель/владелец вручную выбирает обязательства и суммы в пределах доступного. После выплаты 400 OC второму игроку долг первого остаётся 600 OC; вывод организации остаётся запрещён.
- На кошельке 1 000 OC, из них 800 OC в целевом резерве другого обязательства. Ручная оплата долга на 300 OC не допускается: доступно только 200 OC. Повторное нажатие подтверждения не создаёт вторую оплату.

Реализована схема предложений v2: обязательные структурированные financial-поля, зарплата, ставки оплаты за игру/сессию/турнир, киллы и MVP сессии, бонусы за рейтинг и исключения мероприятий.
