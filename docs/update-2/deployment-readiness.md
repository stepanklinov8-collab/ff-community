# Проверка готовности к деплою обновления №2

24 сентября 2026 года, 08:15 МСК. Итог: **к рабочему деплою пока не готово**. Условие владельца «если полностью готово по ТЗ — сделай деплой» пока не выполнено. Рабочий сайт и данные не изменялись, push не выполнялся.

## Подтверждено

- Локальные результаты предыдущей проверки сохраняют силу: успешная сборка, 23 теста модели и импорта, 16 групп SQL-проверок, 26 миграций в PGlite, чистый ESLint и аудит зависимостей.
- Главная ветка удалённого репозитория по чтению `ls-remote` остаётся на `5a9a8146b12d735666a2cf865f3424fb6a8ac0d1`; база рабочей ветки не устарела относительно неё.
- Через Supabase Management API прочитан список доступных проектов: только рабочий `Ff-community`, состояние `ACTIVE_HEALTHY`. Тестовых проектов и веток в доступном аккаунте нет.
- API резервных копий возвращает пустой список; PITR выключен. Это не утверждение об отсутствии чужих внешних архивов, но пригодная для восстановления резервная копия в рамках этой проверки не подтверждена.
- Выполнен только запрос чтения системных метаданных через специальный endpoint `database/query/read-only`. В базе нет `cron.job` и расширений `pg_cron`/`pg_net`. Приватный bucket `competition-evidence` уже существует, но его наличие не подтверждает права и операции нового приложения.
- В репозитории есть GitHub Actions с периодичностью пять минут. Работа отдельного внешнего планировщика раз в минуту и фактическая доставка уведомлений не подтверждены.

## Незакрытые условия выпуска

1. Получить полную свежую резервную копию и проверить её восстановление. Предыдущая выборочная REST-выгрузка для расчётов не заменяет резервную копию SQL/Auth/Storage.
2. Поднять изолированное тестовое окружение, применить все 26 миграций к настоящей схеме и выполнить полный перерасчёт. Сопоставить историю, ставки и кошельки до и после.
3. Проверить реальный сервер с отдельными ролями: черновики, комнаты, обращения, публикации, согласования КВ, исправления и конфликт двух редакторов. Предыдущие UI-проверки использовали искусственный API, а SQL проверялся отдельно.
4. Проверить загрузку доказательств, подписанные ссылки, ZIP и очистку переигровки с настоящим Storage; OCR на реальных игровых скриншотах.
5. Проверить планировщик и доставку уведомлений. Вызов рабочего обработчика во время этой проверки не выполнялся: он изменяет данные и может отправить сообщения пользователям.

После закрытия этих условий разрешение владельца на деплой уже имеется; повторное общее согласие не требуется. Новые расходы или изменения вне согласованного объёма нужно обсуждать отдельно.

Источники проверки: локальные `acceptance.md`, `migration-report.md`, `release.md`; результаты Management API и read-only SQL в игнорируемой папке `tools/database-tests/artifacts/deployment-*-preflight*.json`, `deployment-preflight.json`. Секреты в отчёт не включены.

Справка Supabase: [резервные копии базы не содержат сами файлы Storage](https://supabase.com/docs/guides/platform/backups); [специальный API запросов только для чтения](https://supabase.com/docs/reference/api/v1-read-only-query).
