# Управление ставками по сессиям — 28 сентября 2026

В `/admin/betting` у каждой сессии свой переключатель и собственное время закрытия приёма ставок. Начало или отключение одной сессии не блокирует следующие. До начала выбранной сессии ставки можно отключить и включить снова; уже принятые ставки сохраняются. Новые сессии создаются с выключенными ставками. При миграции старые сессии наследуют существующее состояние своего мероприятия.

Миграция `202609280001_session_betting_controls.sql` добавляет флаг сессии, атомарное административное действие и проверку флага при подтверждении ставки. Изменение блокирует только незавершённые рынки игр этой сессии. Подтверждённые ставки, рассчитанные рынки и выплаты не изменяются. Администраторы и суперадминистратор сохраняют управление; старое право модераторов редактировать сессии не даёт им менять ставки.

Проверки перед выпуском:

- ESLint изменённых файлов и production-сборка — успешно.
- `node tools/database-tests/verify.mjs --betting` — успешно: миграции, основные транзакционные проверки и сценарии ставок, включая независимые сессии, выключение, повторное включение, сохранение выплат, запрет приёма после начала и проверку прав.
- Миграция применена в staging успешно.
- В полном SQL-прогоне найден отдельный сбой теста изменения серии КВ: `clan_war_games_war_game_unique` конфликтует при восстановлении ранее исключённого номера игры. Этот сценарий не изменён данным исправлением; полный прогон не отмечается как успешный. Для проверки ставок добавлен явный режим `--betting`.
- Исправлен диапазон миграций локального тестового стенда: `baseline.sql` описывает схему до обновления №2, поэтому поверх неё применяются миграции с 22 сентября, а не повторно вся историческая схема с `pgcrypto`.
